# 技能行为评估

`scenarios.json` 是任务场景与证据要求，不是基于关键词的自动评分器。
`workflow.py check` 只检查其结构和技能名称，不能证明模型会正确执行这些任务。

## 运行方式

日常小修使用相关场景即可；技能大改选择正例、相似但不触发的任务、跨技能任务和失败场景。
让独立代理读取更新后的技能和最少原始输入，不提供预期答案、怀疑的缺陷或修改结论。

默认只读：允许读取 AGENTS、技能、源码、已有测试和 CLI help；不调用真实写入、编译、测试启动、
烘焙、导出、构建或发布。需要工具执行的结论必须区分“拟执行”和“实际执行”。
若需要行为产物，使用隔离的 runs/临时目录，另按操作范围授权。

可使用如下任务格式，把场景 prompt 原样交给评估者：

```text
读取本项目 AGENTS 和适用技能，处理以下任务。
本次为只读决策评估，不执行写入或启动 Unity 操作。
输出：选择的技能、查阅的源码、下一条准确调用、停止/继续条件、验证与交付范围。
任务：<scenario.prompt>
```

## 判定

逐场景记录实际读取和调用，再由维护者对照 checks：

| 结果 | 条件 |
|---|---|
| pass | 工具、源码、目标和生命周期判断有依据，范围与授权正确，所需证据明确 |
| fail | 编造 API/能力、越过任务终点、未授权操作、错误项目/零测试/残缺产物冒充成功 |
| blocked | 缺少必要原始输入或环境，且无法通过只读分析建立所需结论 |

纯措辞差异不判失败。关键词出现不判通过；读到了 SKILL.md 也不证明遵循其契约。
记录评估者任务、原始场景、关键输出、判定及原因到本次任务或 runs artifact，不修改场景来迎合答案。
只有实际观察到的失败才支持继续修订，避免为假设添加无限规则。

结构/脚本测试、独立决策评估和真实 Editor/设备验证是三类证据，分别报告。
