# TEngine 验证路由

按本次改动的影响面选择证据。执行入口、项目绑定、能力发现和编译/测试终态处理统一交给
[unity-cli](../../unity-cli/SKILL.md) 及其 [操作规程](../../unity-cli/references/operations.md)，
由本项目 `com.unity.pipeline` 提供实际 Editor/Development Player 能力；本页不维护第二套命令。

## 改动与验收

| 改动 | 必要证据与相关场景 |
|---|---|
| 纯文档、技能说明 | 文档结构、链接和引用检查；不为文案形式化连接 Editor |
| 纯 Python 工具 | 相关 Python 测试与实际命令结果；触及 Editor 契约时再做连接验证 |
| C# 实现 | 完整解决方案构建、Editor 编译终态及相关明确测试；新增文件核对实际编译输入 |
| UI 事件/生命周期 | 依据改动验证重复刷新、隐藏或关闭后的回调次数；Widget 销毁顺序与额外订阅归属 |
| 异步资源 | 依据改动验证缓存命中、取消、失败、快速连续刷新、完成时已销毁，核对未接收结果归还 |
| Sprite/图集复用 | 实际目标内容与引用变化；子图重复赋值按当前实现单独观察，不套用散图保证 |
| Prefab/场景/导入设置 | CLI 检查具体资产、组件与引用；C#/.NET 和相关 Unity 验证同时取得证据 |
| 配置消费者 | 与实际生成类编译并运行相关消费场景；结构、模板或导出变动转 [luban-dev](../../luban-dev/SKILL.md) |
| 热更边界/AOT/裁剪 | 程序集引用和入口、Editor 证据；涉及目标平台时另列经授权的 Player/设备验收 |

只改一个格式化方法无需套用全部生命周期场景；修改跨模块所有权、事件框架或公共资源入口时，
覆盖实际受影响的调用方和失败分支。以能发现行为回归的测试为准，不为匹配方法名或文档措辞编写测试。

## 证据的范围

- .NET 成功不能证明 Unity 导入、序列化、资源地址或目标平台正确。新增源码未进入工程时须先解决编译输入问题。
- 默认工作流测试只代表该测试集；业务改动要明确选择相关程序集、分类或用例，并核对实际执行身份和数量。
- 零用例、全部跳过、未取得终态或选中了旧结果均不能验收通过。Editor 断开、忙或多实例时记录真实阻塞。
- 资源任务必须给出具体目标；未传资产或没有运行某设备验证时，不能宣称覆盖整个工程或所有平台。
- 截图用于检查布局、文字、引用等可观察结果，不能单独证明资源释放、交互或发布质量。

交付说明改了什么、实际执行的门禁与结果、运行证据位置，以及未验证项和当前源码限制。
纯文档不需要 .NET/Unity 验证；C# 或资源改动缺少必需门禁时明确列为剩余验收，不能降级为通过。

## 授权边界

普通源码按任务修改；Unity 对象、资产及 Editor 状态写入遵循 CLI 的预览与授权流程。
删除、覆盖资产、包依赖/项目设置、平台切换、真实构建、签名和发布取得对应授权后执行。
开发验证通过不构成发布许可；缺少构建或设备授权时，继续完成已授权的静态和 Editor 检查并记录缺口。
